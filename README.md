# 开发小额staking 产品

## 目标用户及相关质押规则

### 目标用户
小额散户用户：持有零散主网代币，无大额本金，追求低门槛 + 资产流动性

### 核心使用场景
1. 主场景 1：用户连接钱包授权→输入质押代币数量→确认交易→到账质押份额<br>
2. 主场景 2：用户解除质押→提交赎回申请→本金及奖励返还至用户钱包<br>
3. 异常场景：链上 Gas 异常交易失败<br>

### 主要参数
选定：质押资产 = WETH (ERC20 标准包装 ETH)<br>
代币类型：标准 ERC20，18 位小数精度<br>
固定代币地址<br>
Ethereum 主网 WETH：0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2<br>
Goerli测试网 WETH：以实际部署地址为准，合约内由构造函数传入<br>
核心流程强制规范：必须先 approve → 再 transferFrom<br>
所有数量单位：18 位小数精度,wei <br>
禁止重复领取：用户领取奖励后，本地待领奖励清零，历史累计点位重置； <br>
精度误差：统一使用 1e36 放大系数，整除运算无浮点误差、无累积舍入； <br>
Slashing：资产缩水不影响历史已累计奖励，仅影响后续分红权重 <br>

### 业务流程
1. 用户钱包授权合约调用WETH代币 → 发起质押交易 → 合约划转代币 → 记录质押份额与池总量，即刻开始计息（质押最小金额为1个代币，且不能为0，设置单个地址最大质押额50个代币，质押池总质押额5000代币）<br>
2. 系统开始计算收益<br>
3. 用户可随时领取奖励<br>
4. 按总收益抽取手续费<br>
5. 用户可随时解质押取回本金<br>
6. 罚没计算：底层底层节点被以太坊罚没时，整个质押池亏损等额代币，所有质押用户按自己份额占比同比例缩水本金及质押凭证<br>
7. 用户解质押时自动结算未领奖励（防重入，避免重复领取本金和奖励）<br>
8. 更新质押池数量<br>

### 质押奖励规则
1. 计息基准规则:按区块计息，交易上链当前区块即刻生效，新质押/追加质押：当前区块开始累计奖励，部分/全部解质押：赎回区块停止新增奖励，已累计奖励保留<br>
2. 用户质押本金占整个质押池总质押量的比例，瓜分全网每日/每区块产出奖励；质押份额数量等价于份额占比，份额越多分红越高<br>
3. 公式：用户当日奖励 = 当日总奖励 ×（用户质押份额 ÷ 质押池总份额）<br>
4. 奖励来源：从总收益中扣除10%固定比例手续费，剩余进入质押奖励池<br>
5. 奖励注入方式：主动注入，管理员持有收益代币，提前对质押合约 approve；调用 depositReward(uint256 amount) 将税后收益转入合约奖励池；注入即时生效，从当前区块开始参与全网分红。<br>
6. 奖励结算时点：用户解质押时计算奖励并结算<br>
7. 查询奖励：快照模式，查询奖励时实时计算，不实时修改用户数据<br>

### 罚没规则
1. 仅管理员触发，全网质押资产同比例缩水<br>
2. 缩水比例为 比例=新总份额/旧总份额，用户份额 = 持有份额*比例<br>
3. 人工每15天检查节点份额数量并留存记录，当出现亏损，进行上报并进行罚没，亏损金额必须 ≤ 当前质押池总质押量，禁止超量上报<br>
4. Slashing 执行前，需统一结算全网点位，所有用户已产生的奖励全部固化<br>
5. Slashing 执行后，更新全局质押份额，记录罚没数据<br>

### 安全架构
1. 防重入：全局引入 ReentrancyGuard，所有资金交互函数统一加锁<br>
2. 访问控制：基于 Ownable + 函数级 onlyOwner，区分普通用户 / 管理员<br>
3. 紧急暂停：全局开关，故障 / 攻击时暂停核心业务<br>
4. 基础入参校验：零地址、零金额、越界数值 全场景拦截<br>
5. 资金转移容错：统一使用 SafeERC20，兜底 ERC20 转账失败<br>
6. 管理员风控：调用频率、操作灰度、不可越权回滚资产<br>
7. 状态变更规范：严格遵循 Checks-Effects-Interactions(CEI) 模式<br>
